# Platform contracts and reliability

- **SDK/config**: `@saplings/sdk`, `sapling.config.ts`, `SaplingConfig`, `resolveSaplingConfig`. Verified tenant context and fail-closed production settings. Feature registry and app-specific hooks are trusted server APIs. The middleware accepts structural validation schemas, not a dependency on a specific parser.
- **Persistence**: `Store` is transactional and tenant scoped. In-memory writes stage per tenant and commit only on success; external writes serialize and reads see committed state. It is still volatile and unsuitable for production. Drizzle adapter uses PostgreSQL advisory transaction locks and RLS; apply migrations, restricted role, connection pooling, indexes and restore drills. Nested transactions share the outer transaction, not savepoints.
- **Workers**: durable leases/fencing, bounded concurrency, outbox, retries and deadline cancellation. Delivery is at least once; remote actions require idempotency. Real infrastructure, worker crash/recovery, job cleanup and scheduler fairness remain to be validated.
- **Providers**: `adapter-aws`, `adapter-drizzle`, `adapter-app`, `sdk/expanded/providers.ts`. Implemented adapter paths differ from complete service deployments. Use sandbox credentials and separate verified adapter tests; provider matrix lists required config. No secret values in config or logs. Use `../PROVIDER_MATRIX.md`.
- **Realtime**: `@saplings/realtime` exposes LocalBroker, RedisBroker, SSE and optional transports. Redis Pub/Sub is ephemeral, no durable replay guarantee. Per-instance connection limits, session TTL and channel authorization; cross-replica capacity/revocation need verification. Actual Valkey Pub/Sub test added.
- **Middleware**: `@saplings/middleware` uses correlation, logging, permission guards, schema validation, error envelopes, deadline, explicitly anonymous JSON cache and idempotency reservations. Compression and multipart are optional. Side effects must be transactional or reconciled; pending reservations must never be expired blindly. Cache only public content and include all public vary dimensions.
- **Utilities**: `@saplings/utils` original module catalog plus NanoID, browser/server separation. Review original edge cases and browser/Intl/permissions tests. See `../UTILITIES_CATALOG.md` and original source parity.
- **Quality**: separate dev packages and optional minimal runtime instrumentation; no browser/load engine in SDK runtime dependencies. See `QUALITY_EVALUATION.md`.
- **Delivery**: Docker, Kubernetes, Helm and CI templates are not evidence of a deployed environment. Pin dependencies with lockfile, build images, verify SBOM, least privilege, staging load, rollout/rollback and recovery. No external cloud resources are provisioned automatically.
